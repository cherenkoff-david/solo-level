# Запуск приложения локально

Инструкция для тех, кто хочет посмотреть приложение у себя на компьютере и оставить
замечания по интерфейсу. Программировать не нужно: все шаги — это три команды в терминале.

## Что понадобится

- **Node.js** версии **22.18 или новее** — https://nodejs.org (скачайте LTS-версию).
- **npm** — устанавливается вместе с Node.js, отдельно ставить не надо.
- **Git** — https://git-scm.com (на macOS обычно уже есть).

Проверить, что всё установлено:

```bash
node -v    # должно быть v22.18.0 или выше
npm -v
git --version
```

Если `node -v` показывает версию ниже 22.18 — обновите Node.js, иначе приложение не соберётся.

## Шаги

### 1. Скачать проект

```bash
git clone <ссылка-на-репозиторий>
cd Solo
```

### 2. Установить зависимости

Один раз после скачивания (и после каждого обновления проекта):

```bash
npm install
```

### 3. Запустить приложение

```bash
npm run dev
```

В терминале появится строка вида:

```
➜  Local:   http://localhost:5173/
```

Откройте этот адрес в браузере. Всё, приложение работает.

## Как остановить

Вернитесь в терминал и нажмите `Ctrl + C`.

## Если что-то пошло не так

**`Port 5173 is in use`** — порт занят другой программой (или уже запущенной копией
приложения). Это не ошибка: Vite выберет следующий свободный порт и напишет его в строке
`Local:` — просто откройте новый адрес.

**`Unsupported engine` или странные ошибки при запуске** — почти всегда старая версия
Node.js. Проверьте `node -v` и обновите Node.

**Хочу начать с чистого листа** — удалите папку `node_modules` и выполните `npm install` снова.

## Что сейчас можно посмотреть

- Оболочка приложения и навигация: Сегодня / Прогресс / Сферы / Настройки / Финансы.
- Раздел **Финансы** — рабочий.
- Разделы Solo пока показывают экран-заглушку «раздел в разработке» — это нормально, они в работе.

## Чего делать не нужно

- **Docker и Supabase запускать не нужно** — база данных ещё не подключена, приложение
  работает без неё.
- **Создавать файлы `.env` не нужно** — на этом этапе никаких ключей и настроек не требуется.

## Куда писать замечания

Присылайте списком: экран (или адрес страницы), что неудобно или выглядит не так, и, если
можно, скриншот. Формулировки вроде «на этом экране непонятно, куда нажимать» полезнее,
чем «сделайте красиво».
