# Запуск приложения локально

Инструкция для тех, кто хочет посмотреть приложение у себя на компьютере и оставить
замечания по интерфейсу. Программировать не нужно: все шаги — это три команды в терминале.

## Что понадобится

- **Node.js** версии **22.18 или новее** — https://nodejs.org (скачайте LTS-версию).
- **npm** — устанавливается вместе с Node.js, отдельно ставить не надо.
- **Git** — https://git-scm.com (на macOS обычно уже есть).
- **Docker** — https://www.docker.com/products/docker-desktop (нужен для локальной базы Supabase).
- **Supabase CLI** — уже в зависимостях проекта, отдельно ставить не нужно.

Проверить, что всё установлено:

```bash
node -v    # должно быть v22.18.0 или выше
npm -v
git --version
docker info
```

Если `node -v` показывает версию ниже 22.18 — обновите Node.js, иначе приложение не соберётся.
Если `docker info` пишет, что демон не запущен — запустите Docker Desktop.

## Шаги

### 1. Скачать проект

```bash
git clone <ссылка-на-репозиторий>
cd Solo
```

### 2. Установить зависимости

Один раз после скачивания (и после каждого обновления проекта):

```bash
npm install
```

### 3. Поднять локальную базу

Один раз после скачивания (и после изменения миграций):

```bash
npm run db:start:slim   # поднять локальный Supabase
npm run db:reset        # применить миграции и загрузить тестовые данные
cp packages/app/.env.example packages/app/.env.local
npm run db:status       # взять URL и publishable-ключ и вписать в .env.local
```

После `db:status` скопируйте `Project URL` и `Publishable` в `.env.local`:

```bash
VITE_SUPABASE_URL=http://127.0.0.1:54321
VITE_SUPABASE_PUBLISHABLE_KEY=<publishable-ключ из db:status>
```

`db:start:slim` берёт облегчённые образы Supabase. Первый запуск скачивает образы и занимает
несколько минут; дальше запуск быстрый.

### 4. Запустить приложение

```bash
npm run dev
```

В терминале появится строка вида:

```
➜  Local:   http://localhost:5173/
```

Откройте этот адрес в браузере. Всё, приложение работает.

## Как остановить

Вернитесь в терминал и нажмите `Ctrl + C`.

## Если что-то пошло не так

**`Port 5173 is in use`** — порт занят другой программой (или уже запущенной копией
приложения). Это не ошибка: Vite выберет следующий свободный порт и напишет его в строке
`Local:` — просто откройте новый адрес.

**`Unsupported engine` или странные ошибки при запуске** — почти всегда старая версия
Node.js. Проверьте `node -v` и обновите Node.

**Хочу начать с чистого листа** — удалите папку `node_modules` и выполните `npm install` снова.

## Что сейчас можно посмотреть

- Оболочка приложения и навигация: Сегодня / Прогресс / Сферы / Настройки / Финансы.
- Раздел **Финансы** — рабочий, данные хранятся в локальной базе Supabase.
- Разделы Solo пока показывают экран-заглушку «раздел в разработке» — это нормально, они в работе.

## Вход в локальной среде

Тестовый пользователь из `seed.sql`:

- почта: `test@solo.local`
- пароль: `solo-test-password`

Письма для входа по ссылке не уходят наружу: они лежат в Mailpit на `http://127.0.0.1:54324`.

## Чего делать не нужно

- **Подключаться к production-базе для просмотра** — локальная среда использует свой Docker-контейнер, а не облачный проект.
- **Править схему руками в Studio** — изменения не попадут в миграции и потеряются при `db:reset`.

можно, скриншот. Формулировки вроде «на этом экране непонятно, куда нажимать» полезнее,
чем «сделайте красиво».
