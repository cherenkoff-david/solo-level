# Документация проекта

Проект состоит из двух направлений. У каждого — свой домен, свои инварианты и своя документация; общими остаются только инфраструктура (React + Vite + TypeScript, Supabase: Auth + Postgres + RLS), дизайн-токены и оболочка приложения.

```text
docs/
  README.md                  ← этот файл: карта документации
  solo/                      направление «прогрессия»: привычки, опыт, уровни
    overview.md
    product-foundation.md
    progression-system.md
    technical-architecture.md
    user-flows.md
  finance/                   направление «деньги»: план, факт, отклонение
    requirements.md
    data-model.md
    architecture.md
design/                      дизайн: направление, токены, референсы, скриншоты
```

## 1. Solo — прогрессия

Личный трекер привычек и задач с игровой прогрессией: действие → подтверждение → опыт → уровень.

| Документ | О чём | Кому |
| --- | --- | --- |
| [`solo/overview.md`](solo/overview.md) | Что это такое простыми словами | Первое знакомство |
| [`solo/product-foundation.md`](solo/product-foundation.md) | Продукт: проблема, ценности, границы MVP, метрики | Понять «зачем» |
| [`solo/progression-system.md`](solo/progression-system.md) | Правила прогрессии: XP, уровни, сферы, ритм, вехи | Понять «как считается» |
| [`solo/technical-architecture.md`](solo/technical-architecture.md) | Стек, схема данных, безопасность, среды | Понять «как устроено» |
| [`solo/user-flows.md`](solo/user-flows.md) | Экраны и сценарии со схемами (Mermaid) | Понять «как выглядит» |

Порядок чтения — сверху вниз.

## 2. Finance — деньги

Планирование трат и поступлений по дням, фактический учёт и видимость расхождения плана и факта. Независимый раздел: трата не даёт XP, геймификации нет.

| Документ | О чём | Кому |
| --- | --- | --- |
| [`finance/requirements.md`](finance/requirements.md) | Модель «факт / целевой баланс / отклонение», сценарии, экраны, тон | Понять «что и зачем» |
| [`finance/data-model.md`](finance/data-model.md) | Таблицы, инварианты, триггеры, индексы, RLS | Понять «как хранится» |
| [`finance/architecture.md`](finance/architecture.md) | Пакет `packages/finance`, экраны, маршруты, порядок реализации | Понять «как устроено» |

Порядок чтения: требования → модель данных → архитектура.

## 3. Правила

- Документ — источник истины о решениях. Изменение правила в коде без обновления документа считается незавершённой работой.
- Если документ расходится с кодом, исправляется то, что ошибочно; молча расходиться нельзя.
- Существенные решения фиксируются здесь, а не только в переписке.
- Числа прогрессии в `docs/` получаются запуском `npm run gen:progression`, а не набираются руками (см. `AGENTS.md`).
- Правила работы агента и границы направлений — в `AGENTS.md`.

## 4. Что ещё лежит рядом

| Каталог | Что там |
| --- | --- |
| `design/` | Направление интерфейса (`direction.md`), токены (`tokens.md`), референсы, скриншоты |
| `packages/domain/` | Доменный пакет прогрессии: чистый TypeScript, тесты на `node:test` |
| `packages/finance/` | Доменный пакет финансов (план): баланс, планы, серии, снимки месяцев |
| `packages/app/` | React-клиент: оболочка, экраны, токены в `src/styles/index.css` |
